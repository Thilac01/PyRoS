# Beyond ROS 2: Building a Robotics Communication Framework from Scratch Using Python

Exploring robotics middleware, distributed systems and publisher–subscriber communication from first principles.


Since my school days, I have been deeply passionate about robotics. Frankly speaking, my curiosity has never been limited to robotics alone. I have always been drawn to the idea of becoming a polymath exploring different disciplines and understanding how they connect to solve complex problems.
When I first attempted to step into the world of modern robotics, I realized that it was quite different from the traditional robotics I was familiar with.
One of the first things I encountered was the Robot Operating System (ROS). At the time, I had limited access to people with practical experience in ROS, and it was not something I had formally studied as part of my engineering curriculum. Yet, it seemed to be an essential part of contemporary robotics.
Naturally, I started learning through YouTube videos, online courses and documentation. While these resources helped me understand how to build specific applications, I often found myself following instructions without fully understanding what was happening underneath.
I knew how to create a node, publish a message and subscribe to a topic. But I still had questions.
What actually happens when a node publishes a message?
How do independent processes discover and communicate with each other?
What makes a robotics middleware framework different from an ordinary networking application?
Frankly, learning how to use a framework without understanding how it works felt incomplete to me.
So, I decided to take a different approach.
Instead of simply learning how to use ROS 2, why not try to understand it by building something similar from scratch?
That question led me to start developing a lightweight robotics communication framework entirely in Python, beginning with the most fundamental building blocks: sockets, networking, message serialization and inter-process communication.
The goal is not to reinvent ROS 2, but to understand the engineering principles that make it possible.
